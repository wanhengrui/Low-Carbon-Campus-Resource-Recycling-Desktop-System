# 迭代一 · 分支与发布约定（成员3）

## 1. 分支模型

```text
main                     # 成员1 已交付的可编译基线
└─ feature/ui             # 成员3：UI 骨架 + 构建/演示方案
   └─ feature/ui-<topic>  # 迭代二中按页面拆分，例如 feature/ui-search
```

- `main` 始终保持可编译、可运行；合并前必须完成一次代码走查。
- 成员2 使用 `feature/service-test`，不要直接改 `feature/ui`。
- 合并顺序：`feature/ui` → PR → 成员1/2 走查 → `main`。
- 合并前必须验证：`run-ui.bat` 能启动、`start.bat` 控制台 9 步仍通过。

## 2. Tag 约定

| Tag | 含义 | 创建时机 |
|---|---|---|
| `iter1-member1` | 成员1 迭代一交付 | 已存在/由成员1 创建 |
| `iter1-member3` | 成员3 迭代一交付 | 本次提交后 |
| `iter2-ui-skeleton` | 迭代二 UI 主链路可用 | 迭代二评审前 |
| `iter4-release` | 最终可交付版本 | 迭代四打包后 |

```bash
git tag -a iter1-member3 -m "iter1 member3: UI skeleton + design + build plan"
git push origin iter1-member3
```

## 3. 提交信息

格式：`<类型>(<范围>): <说明>`

示例：

```text
feat(ui): 添加登录/主界面 Swing 骨架
docs(iter1): 补充界面清单与复用设计
build(ui): 添加 run-ui.bat 启动脚本
fix(ui): 登录失败时恢复按钮并提示 AppException
```

## 4. 禁止提交

- `target/`、`build/`、`*.class`、`data/*.db`、`__pycache__/`、IDE 配置；
- 任何明文密码、`password_hash`/`salt` 的日志；
- 成员1 的 `docs/01/02/05/06`、`design/`、`db/` 的未授权修改。

## 5. 交接检查

- [ ] `feature/ui` 分支已推送；
- [ ] `run-ui.bat` 可启动；
- [ ] `start.bat` 控制台 9 步未被破坏；
- [ ] `iter1-member3` tag 已创建；
- [ ] 组长已确认成员3 的 Collaborator 权限。
