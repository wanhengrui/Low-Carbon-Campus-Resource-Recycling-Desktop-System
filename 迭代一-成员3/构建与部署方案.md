# 迭代一 · 成员3 构建与部署方案

> 目标：在迭代一交付 **Maven 构建口径 + UI 骨架运行方式 + 部署说明初稿**，不要求本轮产出最终 fat jar。  
> 实际环境：成员1 机器未安装 Maven，采用 `javac --release 17` 离线验证；最终交付在迭代四补 `mvn package` 实测。

## 1. Maven 坐标与插件

| 项目 | 值 |
|---|---|
| groupId / artifactId / version | `edu.campus` / `green-campus` / `1.0.0` |
| packaging | `jar` |
| Java release | 17 |
| 运行时依赖 | `org.xerial:sqlite-jdbc`、`ch.qos.logback:logback-classic` |
| 测试依赖 | `org.junit.jupiter:junit-jupiter`（test scope） |
| 可执行 jar | `maven-shade-plugin`，`Main-Class` 由属性 `main.class` 控制 |

迭代一保持：

```xml
<main.class>edu.campus.recycle.Main</main.class>
```

迭代二起切换为：

```xml
<main.class>edu.campus.recycle.ui.MainApp</main.class>
```

切换前必须同时完成：

1. `MainApp` 在 `run-ui.bat` 下可启动；
2. `mvn test` 通过；
3. `start.bat` 同步改为 UI 入口，或明确保留“控制台/图形界面”两个脚本。

## 2. 目录与资源

```text

├─ lib/sqlite-jdbc-3.42.0.0.jar
└─ data/greencampus.db        # 运行时生成，不入库
```

## 3. 运行命令

### 3.1 UI 骨架（迭代一）

```bat
cd 迭代一-成员1\code\green-campus
run-ui.bat
```

### 3.2 控制台基线（成员1，保留）

```bat
start.bat
```

### 3.3 Maven（有 Maven 的机器）

```bash
mvn -q -DskipTests package
java -jar target/green-campus-1.0.0.jar
mvn test
```

## 4. 数据库与首次启动

- 默认 `db.url=jdbc:sqlite:data/greencampus.db`。
- `MainApp` 只在 `data/greencampus.db` 不存在时调用 `AppController.bootstrapDatabase()`；`--reset-db` 强制重置。
- 工作目录必须是 `code/green-campus`，因为 `db.schema=../../db/schema.sql` 是相对路径。
- 迭代四需把 `db/schema.sql`、`db/seed-data.sql` 打到 jar 资源或复制到 jar 同级 `db/`，并给 `DbConfig` 增加“外部路径 → classpath 资源”的回退。

## 5. 打包风险与待办

| 风险 | 影响 | 迭代四处理 |
|---|---|---|
| 本机无 Maven | 不能在本机验证 fat jar | 在装有 Maven 的机器补跑并保存日志 |
| `db.schema` 相对路径 | 双击 jar 找不到脚本 | jar 内置资源 + 外部 `db/` 双路径回退 |
| `Main` 与 `MainApp` 双入口 | 容易启动错版本 | Maven profile 或启动脚本参数区分 |
| `data/greencampus.db` 重置 | 用户数据丢失 | `DatabaseInitializer` 增加幂等/迁移；UI 只在缺库时初始化 |
| `lib/*.jar` 入库 | 仓库体积大 | 保留成员1决定；Maven 环境可移除 |

## 6. 迭代一验收

- `run-ui.bat` 能启动登录窗；
- `start.bat` 仍能跑控制台 9 步（不破坏成员1基线）；
- `pom.xml` 坐标/插件与本文一致；
- 部署说明初稿包含环境、命令、账号、风险。
