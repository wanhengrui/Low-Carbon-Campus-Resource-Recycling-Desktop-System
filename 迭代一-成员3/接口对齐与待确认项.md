# 迭代一 · 接口对齐与待确认项（成员3提出）

> 目的：把成员3 在 UI 骨架中遇到的接口/构建问题固化为待确认项，避免迭代二开工后反复改 UI。

## 1. Controller 返回值不统一

| 方法 | 当前返回 | UI 影响 | 建议 |
|---|---|---|---|
| `AppController.login` | `LoginResult` | 可判断 success/role/credit | 保持 |
| `UserController.register` | `String` | 只能按“注册成功”前缀判断 | 迭代二统一 `OperationResult<T>`，或保留 String 但禁止解析业务状态 |
| `ItemController.publish/update/offShelf/audit` | `String` | 无法区分成功/失败，只能刷新列表 | 同上 |
| `TradeController.apply/agree/confirm/cancel` | `String` | 同上 | 同上 |
| `ReviewController.review` | 待确认 | 评价后需刷新信用 | 建议返回 `OperationResult` |
| 查询类 | DTO/List/PageResult | 正常 | 保持 |

**临时约定**：迭代一 UI 不回写业务状态；操作后统一刷新列表/详情；注册按“注册成功”前缀做临时判断，迭代二替换。

## 2. 缺失的 Controller 方法

| UI 页面 | 需要的方法 | 现状 | 建议 |
|---|---|---|---|
| 我的物品 | 按 ownerId 查询我发布的物品 | `ItemController` 无 | 成员2 补 `ItemService.findByOwner` + Controller 方法 |
| 我的收藏 | 查询收藏列表 | `FavoriteService` 可能有，UI 无入口 | 补 `FavoriteController` 或在 `AppController` 暴露 |
| 消息 | 发送/查询流转消息 | `TradeController` 只有未读数 | 迭代二补 `TradeMessageController` 或扩展 TradeController |
| 管理后台 | 分类/日志/审核 | `AdminController` 已有部分 | 对齐方法签名后接入 |

## 3. 构建与数据库

1. `pom.xml` 的 `main.class` 仍是 `edu.campus.recycle.Main`；迭代二切 `ui.MainApp` 时，`start.bat` 必须同步，否则启动旧控制台。
2. `DbConfig` 使用 `../../db/schema.sql`，fat jar 双击运行时工作目录不是 `code/green-campus`，会找不到脚本；迭代四必须做资源内置或外部 `db/` 回退。
3. `DatabaseInitializer.initialize()` 每次执行 `schema.sql`（DROP/重建）+ seed；UI 不能每次启动都调用。当前 `MainApp` 只在库文件不存在时初始化，`--reset-db` 显式重置。
4. 本机 PATH 是 JDK 11，成员1 文档写 JDK 17/25；正式验收需在 JDK 17+ 机器补 `javac --release 17` 与 `mvn test` 记录。
