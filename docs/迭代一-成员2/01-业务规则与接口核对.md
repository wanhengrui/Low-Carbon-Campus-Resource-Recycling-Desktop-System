# 业务规则与接口核对

项目为低碳校园资源循环流转桌面系统。本轮核对成员1交付的需求、设计、Java 接口与 SQLite 约束，作为成员2测试设计的依据。

核对来源为 [需求规格 D1](../迭代一-成员1/docs/01-需求规格说明书.docx)、[接口规范 D2](../迭代一-成员1/docs/02-模块化设计与接口规范.docx)、[共享契约 §6、§9、§13](../迭代一-成员1/_共享契约-实体与接口基线.md) 和 [第3轮裁决](../迭代一-成员1/_tools/裁决-第3轮修复清单.md)。取消权限、评价扣分、发布默认状态及新增 DTO 入口采用第3轮口径。表中的错误码是规格预期，运行差异单独登记于[走查记录](03-代码走查与问题记录.md)。

## 业务规则

| 规则 | 核对口径与校验位置 | 本轮核对结果 |
|---|---|---|
| BR-01 注册与改密 | 用户名 4–20 位且唯一，口令 8–20 位且含字母和数字，填写的学号须为 8–12 位数字且唯一。Service 校验格式和重复，库内两个唯一约束兜底。 | 用户名重复返回 DUP-001 已验证。学号重复应为 DUP-002，参考实现仍走通用 DUP-001。学生学号是否必填需要统一 D1 与 Service。 |
| BR-02 口令存储 | PBKDF2WithHmacSHA256，100000 次迭代，16 字节随机盐，256 位摘要。存储层保存盐和摘要，界面及日志不展示二者或原口令。 | 已验随机盐长度、摘要生成、登录、改密换盐。界面与日志完整检查待联调。 |
| BR-03 登录锁定 | 前4次错误返回 AUTH-001，第5次触发 LOCK-001，锁定15分钟。锁定期间正确口令也拒绝，期满后成功登录清零。 | 计数、时限、锁定期间拦截、成功后的清零已验证。第5次提示未告知具体时长，跟随文案复核。 |
| BR-04 信用分与发布 | 默认100分，限制在 [0,150]，变更记录实际增量与变更后分数。最低发布分默认60，低于门槛返回 BR-04。 | 59／60 发布边界、上下限和快照已验。D2「越界即拒绝」与 D1 截断口径不同，采用 D1。 |
| BR-05 单件物品单条在途流转 | 在售物品才能申请，同一物品至多一条 APPLYING／AGREED，部分唯一索引兜底。已售拒绝新申请，按 D2 的专属分支应报 BR-05。 | 在途重复申请已验。已售时当前先走非在售判断并返回 BR-06，另需验证并发数据库冲突到业务码的映射。 |
| BR-06 流转状态和权限 | 出让方同意，双方可确认已同意的流转，双方或管理员可取消在途流转。原因必填，同意、确认和取消的越权细分码分别为 PERM-021／022／023。 | 越权同意、未同意就确认、受让方取消后物品恢复在售已验。权限细分码、原因长度和并发迁移待验。 |
| BR-07 成交原子性 | 物品 SOLD、流转 DONE、双方信用和流水、操作日志在同一 JDBC 事务内成功或回滚。规格成交事务异常使用 TX-001。 | 正常提交和监听器晚期异常后的整笔回滚已验。失败时的异常转换仍与规格不一致。 |
| BR-08 双方互评 | 仅 DONE 可评价，参与方每人一次，评分 1–5 分。1–2 分扣5分，3–5 分信用不变。重复评价应报 DUP-003。 | 已验未完成拒绝、双方可评、重复拒绝、低分扣分及好评不加分。修正了好评重复发放成交奖励。DUP-003 尚未落地。 |
| BR-09 收藏切换 | 首次收藏新增，重复收藏视为取消。收藏记录、列表与物品计数一致，数据库唯一约束兜底。 | 已验顺序切换、列表与计数回到0。写入失败和并发冲突语义仍待验。 |
| BR-10 管理与关联取消 | 管理入口校验管理员身份。下架记录原因并取消在途流转，约定向双方发通知。冻结账号按 FR-16 同时处理该账户在途流转。 | 管理员下架导致取消已验。冻结连带取消、下架通知待实现或确认。 |
| BR-11 关键操作日志 | 发布、修改、审核、登录、流转等操作追加日志，业务入口不提供日志修改和删除。 | 发布、审核、成交追加及回滚已验。物品修改未记日志，失败登录与日志失败策略需对齐 D1。 |
| BR-12 图片校验 | 最多5张，单张不超过2 MiB，限制格式，重命名保存，库内存相对路径。 | 文件数已在 Service 验证，大小上限已在 Validator 验证。完整保存链路需明确由哪一层校验大小、重命名和管理文件。规格写 jpg/png，现有工具也接受 jpeg，待确认统一表述。 |

## 接口及 DTO

D2 §5.4 的7个 Service 共31个方法在 Java 接口中均有对应声明。方法名、参数顺序和返回类型按共享契约 §6、§13 核对。Java 的运行时异常可以不写在 `throws` 中，仍须根据 D1 校验实际的异常类型与错误码。

| Service | 核对结果与交接点 |
|---|---|
| UserService（9） | `updateCredit(int userId, int delta, Integer flowId, String reason)` 与最新契约一致。`getCredit` 返回 `UserCreditDTO`，当前提供信用等级与变更计数，D2 关于返回近期流水列表的说明需修订或补接口。 |
| ItemService（6） | `search(ItemQuery)` 返回 `PageResult<Item>`，默认范围为在售，显式状态仍可用于管理查询。物品审核实际归 `ItemService.audit`。 |
| FavoriteService（2） | `toggle` 返回收藏完成后的布尔状态，`listByUser` 返回物品列表，正常切换与数据库计数已交叉验证。 |
| TradeService（7） | `historyDetail` 返回 `List<TradeDetailDTO>`，`countUnread(int)` 已声明。FR-10 所需发送消息与标记已读目前只有 DAO 相关操作，需确认 Service／Controller 接口与权限。 |
| ReviewService（1） | `review` 返回评价实体，反例另核对未完成、越权、重复和错误码。 |
| StatisticService（3） | 接收明确的起止时间，返回分类统计、总减排或 CSV 路径。导出写文件的声明包含 `IOException`，交互层调用方式需同步。 |
| AdminService（3） | 分类维护和日志查询已声明。账号冻结归 `UserService`，审核及下架归 `ItemService`。`recentLogs(int limit)` 的操作者身份从哪里传入需要补齐。 |

`PageResult` 字段为 `records / total / pageNo / pageSize / totalPages`。`StatisticsDTO` 按第3轮裁决保留分类、笔数、金额、减排4字段。`ItemQuery` 的现有字段包含价格、状态和排序，FR-08 的成色筛选参数尚未在 DTO 中落地。其余已声明 DTO 与当前类图的字段对照结果见成员1的 [cross_check.txt](../迭代一-成员1/_tools/cross_check.txt)。
