# 部署说明（迭代一 · D7 Maven 工程骨架）

> 适用对象：成员2（业务逻辑与测试）、成员3（GUI/复用/交付）、验收教师。
> 本文只写**已在本机实际执行过**的命令；未执行的命令在文中明确标注"未执行"。

## 1. 环境要求

| 项目 | 版本要求 | 本机实际（迭代一验证环境） |
|---|---|---|
| JDK | 17 及以上（编译目标 17） | Oracle JDK 25.0.2，编译时统一加 `--release 17` |
| Maven | 3.8 及以上（可选，见第 3 节） | **本机未安装**，因此本轮未执行任何 `mvn` 命令 |
| 操作系统 | Windows / macOS / Linux 均可 | Windows 11 |
| 数据库 | SQLite（文件型，无需安装服务） | sqlite-jdbc 3.42.0.0（运行期驱动） |

## 2. Maven 构建与运行（推荐路径，需联网下载依赖）

```bash
cd code/green-campus
mvn -q -DskipTests package          # 编译 + 打 fat jar（maven-shade-plugin）
java -jar target/green-campus-1.0.0.jar
mvn test                            # 运行 JUnit 5 用例（11 条）
```

- 主类：`edu.campus.recycle.Main`（迭代一控制台版骨架）；迭代二的 Swing 入口为 `edu.campus.recycle.ui.MainApp`。
- 首次启动会自动执行 `../../db/schema.sql` 建库、`../../db/seed-data.sql` 灌入演示数据，数据库文件落在 `code/green-campus/data/greencampus.db`。
- 依赖版本集中在 `pom.xml` 的 `<properties>`：`sqlite-jdbc`、`logback-classic`、`junit-jupiter`。

## 3. 无 Maven 时的离线验证（本机采用的方式，已实测）

本机未安装 Maven，迭代一全部验证改用 JDK 自带工具完成，命令如下（在 `code/green-campus` 目录执行）：

```bash
# 3.1 编译主源码（107 个 .java）
javac --release 17 -encoding UTF-8 -d build/classes @build/sources.txt
#   sources.txt 由 dir /b /s src\main\java\*.java 生成（路径为相对工程根目录）

# 3.2 编译并运行 JUnit 5 用例（2 个测试类 / 11 条用例）
#   classpath 需包含 junit-jupiter-api、junit-platform-commons、opentest4j、apiguardian
java -jar junit-platform-console-standalone-*.jar --class-path "build/classes;build/test-classes" --scan-class-path

# 3.3 运行控制台主程序
java -cp "build/classes;src/main/resources;lib/sqlite-jdbc-3.42.0.0.jar" edu.campus.recycle.Main
```

**两个必须注意的坑（已踩过）**：

1. **工作目录**：`application.properties` 中 `db.schema=../../db/schema.sql` 是相对 `code/green-campus` 的路径，必须在该目录下运行，否则报"建库脚本不存在"（程序以退出码 0 中止，容易误判为成功）。
2. **classpath 必须包含 `src/main/resources`**：否则 `ConfigManager` 读不到 `application.properties`，会静默回退到内置默认值（连接串、脚本路径都变），现象是"配置文件改了不生效"。
3. 若用 `javac @argfile` 传源文件清单，PowerShell 的 `Set-Content -Encoding utf8` 会写入 BOM 导致"无效文件名"，请用 `-Encoding ascii`。

## 4. 双击运行

双击 `start.bat`，脚本按以下顺序自适应：

1. 若存在 `target/green-campus-1.0.0.jar` → 直接 `java -jar` 启动；
2. 否则若检测到 `mvn` → 先 `mvn -q -DskipTests package` 再启动；
3. 否则（无 Maven、无 jar）→ 用 `javac` 离线编译到 `build/classes` 后启动，依赖 jar 依次从 `lib/sqlite-jdbc-*.jar`、`%USERPROFILE%\.m2\repository\org\xerial\sqlite-jdbc\` 查找；
4. 三者都不可用 → 明确报错并指向本文第 3 节。

离线场景把 `sqlite-jdbc-<版本>.jar` 放进 `code/green-campus/lib/` 即可（`lib/` 不入库，`.gitignore` 已忽略）。

## 5. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `建库脚本不存在：...\db\schema.sql` | 工作目录不是 `code/green-campus` | `cd` 到工程根目录再运行，或用 `start.bat` |
| 配置修改不生效 | `src/main/resources` 不在 classpath | 按第 3 节第 3.3 条补上 |
| `No suitable driver found for jdbc:sqlite:` | 缺 sqlite-jdbc 驱动 | Maven 构建，或把驱动 jar 放入 `lib/` |
| 演示数据重复/脏 | `data/greencampus.db` 为旧库 | 删除 `data/greencampus.db` 后重启（会重新建库灌数据） |
| 中文控制台乱码 | Windows 控制台代码页 | `start.bat` 已 `chcp 65001`；手工运行时先执行 `chcp 65001` |
