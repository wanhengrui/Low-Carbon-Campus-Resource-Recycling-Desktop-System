# 迭代一·共享契约（Single Source of Truth）

> 本文件由 Lead 维护，是 D1/D2/D3/D4/D5/D7 的**唯一字段与签名基线**。任何队友不得修改本文件；
> 需要变更契约（加字段、改方法名、改表名）必须先 `send_message` 报 Lead，由 Lead 修订后广播。
> 本文件不随交付物提交（以 `_` 开头），但其内容必须体现在各交付物中。

- 项目：低碳校园资源循环流转桌面系统（GreenCampus Recycle）
- 课程：《软件构造》8 周分组实验，3 人小组，每 2 周一个迭代
- 本轮：迭代一（第 1–2 周：需求与设计），交付人：成员1（系统设计与数据层）
- 技术栈：**Java 17 + Maven + SQLite（xerial sqlite-jdbc）+ JDBC + Swing + JUnit 5**；禁止 Spring / 禁止 ORM
- 数据库文件：`greencampus.db`（程序运行目录），初始化脚本 `db/schema.sql` + `db/seed-data.sql`
- Maven 坐标：`groupId=edu.campus`，`artifactId=green-campus`，`version=1.0.0`，`maven.compiler.release=17`

## 1. 包结构（不得改动根包名）

```
edu.campus.recycle
├─ ui           表现层（Swing 窗体、面板、事件监听）
├─ controller   控制层（UI 与 Service 的适配、参数校验入口、结果封装）
├─ service      业务接口层
│  └─ impl      业务实现层
├─ dao          数据访问接口层
│  └─ impl      数据访问实现层（JDBC）
├─ entity       持久化实体（与表一一对应）
├─ dto          跨层传输对象（查询条件、统计结果、聚合视图）
├─ util         工具类（DbUtil/CsvExporter/PasswordUtil/Validator/DateUtil/LogUtil）
├─ exception    自定义异常体系
└─ config       配置（DbConfig/AppConfig）
```

依赖方向：`ui → controller → service → dao → (entity, util, exception, config)`。**禁止反向依赖**，禁止 ui 直接调 dao。

## 2. 术语与命名规范

| 概念 | 统一用词 | 禁止用词 |
|---|---|---|
| 闲置物品 | 物品（Item） | 商品、货物 |
| 流转 | 流转（TradeFlow），含成交/交换/赠送 | 订单、交易单 |
| 意向沟通 | 沟通消息（TradeMessage） | 聊天、私信 |
| 信用分数 | 信用分（creditScore，初始 100，区间 0–150） | 积分、信誉值 |
| 分类 | 分类（Category，两级：父分类/子分类） | 类别、类型 |
| 管理员 | 管理员（ADMIN） | 超级用户 |

- 表名/字段名：小写 + 下划线（`trade_flow`, `created_at`）；Java 属性：驼峰。
- 布尔字段：DB 用 `INTEGER`(0/1)；Java 用 `boolean`，命名 `isXxx`。
- 时间字段：DB 用 `TEXT`（ISO-8601 `yyyy-MM-dd HH:mm:ss`），Java 用 `java.time.LocalDateTime`。
- 金额字段：DB 用 `REAL`（单位：元，保留 2 位），Java 用 `java.math.BigDecimal`。
- 枚举：Java 用 `enum`，DB 用 `TEXT` 存枚举 `name()`，并用 `CHECK` 约束限定取值。
- 主键：`INTEGER PRIMARY KEY AUTOINCREMENT`；外键统一 `<表名单数>_id`。
- 需求编号：`FR-01…`、`NFR-01…`、`BR-01…`（业务规则）、`UC-01…`（用例）——全组统一，**不得另起编号体系**。

## 3. 数据库表基线（11 张表，字段级唯一口径）

> 建表顺序按外键依赖：`user → category → item → item_image → favorite → trade_message → trade_flow → review → credit_log → operation_log → system_config`

### 3.3 `item` 闲置物品
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 物品ID |

| tags | TEXT | | 标签，逗号分隔（设计权衡见 D5 说明） |
| status | TEXT | NOT NULL DEFAULT 'ON_SALE' CHECK IN ('DRAFT','PENDING','ON_SALE','LOCKED','SOLD','OFF_SHELF','REJECTED') | 物品状态 |

## 7. 异常体系（exception 包）

```
AppException (extends RuntimeException)  ── 字段：String code; String userMessage
├─ ValidationException        code=VAL-xxx
├─ DuplicateEntityException   code=DUP-xxx
├─ EntityNotFoundException    code=NF-xxx
├─ AuthenticationException    code=AUTH-xxx
├─ AccountLockedException     code=LOCK-xxx
├─ PermissionDeniedException  code=PERM-xxx
├─ BusinessRuleException      code=BR-xxx（携带违反的 BR 编号）

└─ TransactionException       code=TX-xxx
```
- 工厂方法统一：`AppException.of(code, userMessage, cause)`。
- UI 层只捕获 `AppException`，按 `code` 映射提示文案；未捕获异常写 `operation_log` + 日志文件。

## 8. 设计模式落点（5 处，报告需写清"用在哪 / 解决什么问题"）

| # | 模式 | 落点 | 解决的问题 |
|---|---|---|---|
| 1 | 单例 | `DbUtil`、`ConfigManager` | 避免多次打开 SQLite 连接、配置重复解析 |
| 2 | 工厂 | `DaoFactory`（按枚举返回 DAO 实现）、`ServiceFactory` | 上层不 new 实现类，替换实现/测试 mock 不改调用方 |
| 3 | 策略 | `ItemSortStrategy`（最新/价格升/价格降/信用优先）、`CarbonFactorStrategy`（按分类取减排系数） | 检索排序与减排估算算法可插拔，新增排序不改 ItemService |
| 4 | 观察者 | `ItemEventBus` + `CreditChangeListener` / `OperationLogListener` / `StatisticListener` | 流转完成时解耦"改物品状态 / 记信用 / 写日志 / 统计" |
| 5 | 模板方法 | `AbstractJdbcDao.executeInTransaction(...)`、`AbstractCsvExporter.export(header, rows)` | 统一 JDBC 资源释放、事务提交回滚、异常转换，消除 try-catch-finally 重复 |
| 6（备选） | 建造者 | `ItemQueryBuilder` | 多可选检索条件组合，避免超长参数表 |

## 9. 业务规则基线（BR）

- **BR-01** 用户名 4–20 位 `[A-Za-z0-9_]`，唯一；密码 8–20 位且必须同时含字母与数字；学号 8–12 位数字且唯一。
- **BR-02** 密码以 PBKDF2WithHmacSHA256（100000 次迭代、16 字节随机盐、256 位密钥）存储，**任何日志/界面不得出现明文或盐**。

- **BR-04** 信用分 < 60 的用户禁止发布物品；信用分区间 [0,150]，变更须写 `credit_log` 快照。

- **BR-09** 收藏唯一（user_id + item_id），重复收藏视为取消收藏（toggle 语义）。
- **BR-10** 管理员可下架任何 `ON_SALE`/`PENDING` 物品（记 `audit_remark`）与冻结用户；被下架物品的进行中流转自动取消并通知。

## 13. 第 3 轮裁决（v1.1，2026-11-02，Lead 冻结；与 `_tools\裁决-第3轮修复清单.md` 同源，冲突以清单为准）

1. **错误码两级制**：需求层语义码（`VAL/DUP/NF/PERM/AUTH/LOCK/DB/TX` + 三位数字）用于需求与界面文案；模块层细分码（`DB-1xx`/`NF-0xx`/`PERM-0xx`/`TX-0xx`/`DUP-0xx`）用于日志与测试断言。D1 增"错误码总表"登记全部细分码；同一业务异常只允许一个码（重复评价 = **DUP-003**，分类重名 = **DUP-004**）。
2. **BR 编号一律两位**：`BR-01…BR-12`；异常 code 同写法（如 `BusinessRuleException.of("BR-04", …)`）。
3. `PageResult<T>` 字段：`records / total / pageNo / pageSize / totalPages`（无 `rows`）。
4. `void updateCredit(int userId, int delta, Integer flowId, String reason)`（flowId 在 reason 之前）为唯一签名。
